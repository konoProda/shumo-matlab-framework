# 建模手交接文件夹说明

本文件夹用于集中管理**编程手与建模手之间的全部往来文件**，与组内产物（`outputs/`）、
题目数据（`data/`）、交付面（`deliver/`）分离，避免混放。

## 目录结构

```
建模手交接/
├── 交付建模手/      # 编程手 → 建模手：确认单、回执等
├── 接收自建模手/    # 建模手 → 编程手：建模文档、确认结果等
└── 说明.md          # 本文件
```

## 两个子文件夹各放什么

### `交付建模手/`

| 文件类型 | 命名 | 何时产生 |
|---|---|---|
| 确认单 | `致建模手_确认点N_qX.md` | 每次进入三个关键确认点时 |
| 回执 | `致建模手_确认点N_qX_回执.md` | 编程手处理完建模手回复后 |

写作要求见 CLAUDE.md §确认点交付单，四条底线：

1. 面向建模手，不出现 MATLAB/代码/求解器细节；
2. **不提编程侧路径**——文档中不得出现本队的项目名、目录名、文件名或任何路径；
   引用建模手来文只写《文件名》，引用编程侧产物改为职责描述并注明"你无需阅读"；
3. **AI-ready**——元数据块声明工作量、条目编号 `Cn`/`Gn` 稳定、状态显式标注
   `【需回复】`/`【仅告知】`、需回复项固定四段结构、结尾给键值式填写块；
4. 需回复项 ≤2 个选项、3 分钟可回完；凡属"已由数量关系或题面唯一确定"的事项一律降级为告知项。

### `接收自建模手/`

| 文件类型 | 示例 | 说明 |
|---|---|---|
| 建模文档 | `问题一_建模交接与算法实现(2).md` | 逐问交付的数学模型，/prep 的输入 |
| 确认结果 | `问题一_确认结果交接给编程手.md` | 建模手对确认单的回复，**须为一份文档** |

**命名约定**：建模手来文一律以 `问题X_` 开头，便于按问归档。

**回传件须为文档**（2026-09-11 立）：建模手的回复不接受零散口头/聊天文字，须以**结构化的文档**
回传——确认单第五节给出固定模板（键值式逐条 `Cn = A/B` + 补充说明），建模手可直接让 AI 依此填充生成。
理由：回传件是留档与后续追溯口径的依据，散文字无法归档、也无法被 AI 稳定解析。

## 与工作流的关系

- 建模文档是 `/prep` 的输入 → 解析产物写入 `outputs/*_qX.md`
- 确认单与回执**只进出本文件夹**，不写入 `outputs/`
- 建模文档修订后重跑 `/prep`，幂等覆盖该问产物，但**本文件夹中的历史来文一律保留不删**
  （保留演进痕迹，便于回溯口径变化）

## 注意

建模手使用独立设备与路径，其文档中出现的本机路径（如 `D:\...`）**不适用于本队**。
编程侧的目录与命名一律按本项目规范执行。
