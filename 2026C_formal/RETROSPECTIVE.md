# 第五轮：问题二·7 日滚动 SAA 两阶段 MILP（2026-09-12）

## 一、本轮发生了什么

建模手推翻此前的"全年视野滚动 LP"与预测层校正方案，改为**两层结构**：
第一层理想信息确定性 MILP 作基准，第二层 **7 日滚动 SAA 两阶段随机 MILP** 作现实主模型；
第一阶段变量只有当天计划购电量 `G^plan`（全情景共用），第二阶段逐情景展开物理调度。
编程侧落地为七组运行（L1 逐日理想 / L1b 全年联合理想 / L2 正式 / L2b 消融 /
L2r1、L2r3 视野对照 / L2k8 情景数稳定性）。

## 二、流程事故与固化措施

**R8（事故）长跑无断点，被内核 OOM 杀掉后白跑**

本机物理内存 3.868 GB，而实测 MATLAB 空跑常驻 805 MB、满载约 3.0~3.2 GB，
桌面与终端常驻约 450 MB——**余量不足 0.5 GB**。2026-09-12 20:01、20:02 两次
`Out of memory: Killed process (MATLAB)`（exit=137，内核日志可查），
**被杀的是两次轻量的静态检查（`checkcode`）**——连静态检查都能耗尽内存，
可见余量之小。六组运行中最大的一组（K=8、8.7 万列）风险最高。

**固化**：
① 凡预计超过 5 分钟的跑批，**必须每 N 天落断点**（本轮取 20 天），跑批脚本自动重试，
并加"连续两次无断点写入即熔断"（区分"随机被杀"与"固定卡点/代码错误"）；
② **断点续跑的正确性必须自证**，不得想当然——本轮用探针实测
「续跑第 41 天」与「全量重跑第 41 天」的费用与 SOC 序列逐位一致（最大差 0.000e+00）后才放行；
③ 跑批期间**禁止开第二个 MATLAB**（既有铁律，本轮补上了量化依据：第二个进程必然触发 OOM）。

**R9（事故）后台任务未脱离会话进程组，被会话层动作连带杀死**

19:50 六组运行在 L2 第 180 天日志戛然而止：**无报错、无 OOM 记录、无退出码**。
原因是后台进程与会话同属一个进程组，会话压缩/切换时被一并终止。

**固化**：长跑一律 `setsid nohup … &` 脱离进程组，并按"日志是否有结束标记"
判断存活，不以"进程还在不在"为准。

## 三、本轮有效的做法（建议保留）

**P5 断点续跑 + 正确性自证一起做**：只加断点不自证，等于把"可能算错"换成"算得快"。

**P6 开工前先量环境**：本轮先量了 MATLAB 空跑/满载内存与机器总量，
才知道"3 GB 环境"这条既有约束到底还剩多少余量，也才知道该加多密的断点。

**P7 独立复核子 agent 第三次抓到主流程看不见的真问题**：本轮复核 agent 用 Python
独立重实现了预测层、偏差层、执行层与单日确定性模型并逐位比对（最大差 ≤1e-11），
据此确认主链路可信；同时抓到"每日重置种子 ⇒ 全年同一置换"这一**抽样退化**——
主流程此前把它当成"已按规定实现"，从未质疑。该模式（只读、独立重算、给反例）
建议固化为每个模型轮次的收尾步骤。

## 四、本轮新增事故与固化

**R10（事故）"重置种子"被当成"独立抽样"：文档说独立，代码给的是固定模板**

`func_scen_q2c` 原按 G4 字面写 `rng(seed)` 每日重置。因残差库长度恒为 28、
种子恒定，`randperm(28,4)` **全年返回同一个置换**：每天都抽"固定的 4 个相对滞后"。
文档 G4 的括号注写的是"即每天独立可复现"——**可复现做到了，独立没有**。
影响：SAA 情景每天高度重叠，且若误差分布存在滞后结构会被系统性放大；
更重要的是论文若写"随机无放回抽取"，与代码实际行为不符。

**固化**：
① 实现"随机抽样"后，必须验证**抽样本身是随机的**（连跑相邻若干日，看抽中的
相对位置是否变化），不能只看"能复现"；本轮已把该判据写进 `tests/test_q2c.m` T11；
② 文档里凡是**括号补注**（"即……"）的口径，一律按正文口径核代码，不得用补注替代判据；
③ 发现后按"口径修正"流程处理：修正内部文档 + 列入回传告知项 + 保留旧口径结果作对照，
  并重跑受影响的所有组（本轮重跑六组，约 35 分钟）。

**R11（流程）修改源码与跑批并行 —— 差点造成混版拼接**

R8 的续跑机制上线后，若在**某组已落断点之后**修改 `src/*.m`，续跑会得到
"前半段旧代码 + 后半段新代码"的拼接结果，而当时的断点签名只看参数、看不到源码版本。
本轮已实证存在该场景（L1 于 19:45 用旧版跑完，20:00 才加入断点机制）。

**固化**：① 断点签名必须含**源码指纹**（本轮取全部 `src/*.m` 内容的滚动指纹）
与 `prm`／`use_bin`／`cfg.W` 等全部数值相关参数，签名不符时**打印作废提示**而非静默重跑；
② 长跑进行中**禁止编辑 `src/`**——MATLAB 会按时间戳重载函数，边跑边改等于自己制造混版。



> 用途：**下次工作流优化的唯一流程依据**（产出标准看范文，流程设计只认本文件）。
> 本文件按轮次累积。R 编号全局唯一，不重号、不覆盖。

# 第四轮：问题二·预测层偏差校正（2026-09-12）

## 一、本轮发生了什么

问题一、二、三都已按各自口径"做完"之后，团队人工讨论推翻了两个基础口径：

1. **一月不需要预测**——2025-01-01 ~ 01-31 应作为"已知数据"直接进计划层，并充当后续预测的
   历史样本；这正是结果表自 2 月 1 日起填报的原因。此前建的三套冷启动规则
   （首日用附件1 典型日、初期用扩展均值回退、一月预热）**全部是自造假设**。
2. **问题二三的思路仍有偏差**——建模手随后给了《问题二_预测层局部优化方案》，
   要求在预测层加入因果分时偏差校正，并以 B0~B3 四方案对照验证。

实施过程中又查出两处更基础的时间轴缺陷（见 R1、R2）。

## 二、流程事故与固化措施

**R1（事故）口径修订只做了一半：同一个附件，改了一列忘了一列**

2026-09-11 的时间轴修订把附件标签改读为"起始时刻"，并给负载、光伏加了跨日取值；
**同一个附件1 的电价列却漏了相位归位**。后果是问题二、问题三每个时段拿到的都是
后一个时段的电价，整条电价曲线相对负载与光伏提前 10 分钟，且与问题一的口径不一致
（问题一的读取函数当时做了右移）。直到建模手的新方案文档 §3 点名"不能错配至 23:50 槽"
才暴露。

**固化**：口径修订必须按"**附件 → 每一列 → 每一个消费者**"三维核对，不得只改出问题的那一列；
核对结果写进 `preprocess_log`，并在读取函数里留下与文档同源的断言。
本轮已按此把电价/负载/光伏三列与四个消费者（问题一/二/三 + 各探针脚本）逐项过了一遍。

**R2（事故）"缺失值回退"实质上是用未来值冒充已知**

2025-01-01 的 `[0:00,0:10)` 槽在附件2 中不存在，代码取"本日末列"填补。该列的真实含义是
**2025-01-02 00:00–00:10 的实测值**——既是未来数据泄漏，又与第 2 日首槽重复。
这行写法在代码注释里被记为"边界约定"，形式上"已记录"，实质上仍违规。

**固化**：凡"缺失值回退"，除记录处理方式外，必须额外过一遍
"**这个值在决策时刻是否可知**"；不可知者一律不允许进入模型。
可接受的替代是明确标注的冷启动假设（本轮改为附件1 典型日值，并单独披露）。

**R3（事故）需求理解偏差：报告窗口的起点含义没有在 /prep 追问**

"结果表为什么从 2 月 1 日开始填"是题面给出的强信号，但 /prep 阶段默认接受了
"一月是过渡期、需要冷启动预测"这一可自洽的读法，据此建了三套自造假设，
三轮跑完之后才被人工讨论推翻。返工代价：问题二全量重跑（5 次全年运行）+ 文档重写。

**固化**：/prep 阶段增加一条**显式追问**：题面/模板中所有"窗口、编号、格式"上的
非常规设计（为什么从这里开始、为什么这样编号、为什么留这一格），
必须逐条给出"题面想要的是什么"的判断并写进 decisions，不得默认接受可自洽的读法。
与本条并列的既有事故补丁：2024C R1（求解风险预判前置）、2024C R5 / 2025C（图件清单前置）。

**R4（事故）静态换算被当成修复后的真实影响**

电价相位错位的影响，用"同一份既有计划换价目表、不重解"估算为 **+31.24 万元（+1.59%）**；
重解后实际只有 **+4.68 万元（+0.24%）**——计划层会把购电从"错价时段"挪到真正便宜的时段，
抵消了大部分静态损失。两者差 7 倍。

**固化**：凡"改一处输入后费用会变多少"的判断，**必须重解后汇报**；
静态换算只能标注为"量级上界参考"，不得写进结论、不得用于决策。
本轮的回传报告在此处专门加了替换说明，确认单里也补了更正条目。

**R5（流程）测试失败要先判定"是测试还是代码"**

本轮 5 项测试失败**全部是测试自身的缺陷**：取错输出位置（`[~, p1, ~]` 取到的是第二个输出）、
扰动区间没落在估计窗口内、守恒式漏了未消纳项、`max` 用了向量化形式、
`readcell` 区域取了 (2:1+T) 导致列主序错位。
若不加分辨地"改代码迁就测试"，会引入真 bug；若不加分辨地"改测试迁就代码"，会漏掉真问题。

**固化**：测试失败时，先在日志里写明"判定为测试缺陷 / 代码缺陷 / 数据缺陷"及依据，
再动手；判据尽量写成可独立复核的形式（本轮的做法是把判据改成解析可验的恒等式）。

**R6（事故）新增跑批入口没有接上交付链路**

`func_roll_q2` 的输出结构缺 `rep_idx / price_v / day_list` 三个字段，
而写出函数需要它们；新入口 `main_q2b.m` 又没有调用写出函数。
结果是 B0~B3 四个方案跑完后**产不出交付件** `result2.xlsx`。
该断点由独立复核的子 agent 发现，不是主流程自查发现的。

**固化**：新增/替换"跑批入口"时，必须同时确认三件事——
① 与既有结果文件的数据结构对齐；② 交付件可产出；③ 测试里加一条"交付件可产出/可读"的判据。
本轮已补 `scripts/write_q2b_deliver.m`，并在 `tests/test_q2b.m` 的 T10 加了列映射判据。

**R7（流程）模型口径变更后的"陈旧假设"扫描**

"一月按已知"只改了一个函数的几行，但全库有 30+ 处注释、探针脚本、文档仍在假设旧口径
（冷启动、一月预热、校正自 2 月 1 日起）。人工找必漏。

**固化**：模型口径变更后固定做一次**全库扫陈旧假设**（可并入 /code 的收尾步骤），
输出"必须改 / 应当改 / 可选"三档清单。本轮由子 agent 执行，抓到 3 处仍在生效的旧口径代码
（其中 `cmp_q2_lexico.m` 一月仍按预测排计划、`main_q2_forecast.m` 同类）与 20+ 处过时表述。

## 三、本轮有效的做法（建议保留）

**P1 子 agent 并行 + 独立复核**

本轮把四类工作并行分派：① 全库扫陈旧假设；② 新增改动的边界正确性复核；
③ 三份文档的数值落盘；④ 图件重出。其中**独立复核抓到了主流程自查没发现的三个真问题**
（交付链路断点、`corr.on` 语义被重载成"窗口达标"而非"校正生效"、追溯字段缺失）。
"让另一个 agent 只读复核"比"自己再看一遍"有效，建议固化为 /code 之后的可选步骤。

**P2 数值块程序直出，杜绝手抄**

诊断脚本 `scripts/report_q2b.m` 除打印外，直接写出 `outputs/q2b_handback_tables.md`
（表A~表E 的 Markdown），回传报告与实现报告的数字全部从中取。
避免了"报告数字与 outputs 不一致"这一类最难查的错误。

**P3 把口径写成断言**

"改动决策日之后的实际数据，决策日的预测、校正量、购电计划必须逐位不变"——
这类因果关系写成测试断言（本轮 T5），比人工检查可靠。

**P4 反直觉结论必须拆解成因**

本轮的核心结论"引入后续时刻预报反而使费用上升"（第三轮）与"校正收益全在后段、
前段为负"（第四轮）都是反直觉的。两次都做了拆解（费用项分解、分段对照），
并把适用范围限制写进结论。建议固化：**凡结论与直觉相反，必须给出成因拆解与适用范围限定**，
否则不得进论文。

## 四、遗留与下一轮必须处理的

1. **问题三需按"电价相位修复 + 一月按已知"一次性同步重跑**——两条口径变更叠加，
   分两次跑等于白跑一次。问题三的既有数字（1,997.87 万元等）在重跑前不得引用。
2. **问题二交付件 `result2.xlsx` 待按选定配置重写**——现有文件是旧时间口径的产物，
   测试 T10-4 已标注"待重写"。
3. **问题二全部图件需按新结果重出**——旧图件的数据源属作废口径。
4. **理想基准（逐日完美信息 / 全年联合）本轮未按新口径重跑**，其数字不得引用。
5. `cmp_q2_lexico.m`、`main_q2_forecast.m` 等探针/退休入口仍按旧口径（一月预测）运行，
   其历史结论（如"不同天数为 0"）若被引用须先说明口径。
