# /code - 代码生成

> **逐问模式（2026-09-11）**：本次只生成**当前一个问题**的代码——问题号取自 `.active_problem.txt`
> 第三字段，或由 `/code <题目名> Qn` 显式指定；只读该问的 `decisions_qX.md` 与 `math_to_code_mapping_qX.md`，
> 状态文件写为 `<题目名>|Phase1|QX`。详见 CLAUDE.md §逐问求解模式。

## 触发条件
仅在用户通过 /prep 确认后，或手动输入 /code 时触发。
- 支持显式指定题目：`/code <题目名>`（如 `/code A题`）；未指定时读取 `shumo/.active_problem.txt` 中的当前题目。
- 状态文件为空且未指定题目名时，先询问题目名，不得默认猜测。
- 执行任何文件写入前，先在回复中列出目标目录树 `shumo/<题目名>/...` 供核对。

## 执行流程
0. 覆盖检查：若 `<题目名>/src/`（或按需的 scripts/、tests/）已存在同名 .m 文件，先备份为 `*.m.bak_<时间戳>`；在回复中列出"本次将创建/覆盖的文件清单"后再写入。
1. 致命错误检查清单：
   - 矩阵维度：`*` 与 `.*`、`'` 与 `.'`（复数转置）、broadcast 兼容性；
   - 循环：while 必须有终止条件 + 最大迭代次数护栏；for 循环内禁止修改迭代变量；
   - 递归：必须有出口条件；
   - 维度函数：size/length/numel 语义正确（length 对非向量矩阵返回 max(size)）；
   - 数值风险：除零、索引越界（end+1）、整型截断。
   - 绘图环境陷阱（R2026a）：`bar()` 语义为"行=组、列=每组柱数"（与经典 MATLAB 相反），
     使用前以探针确认方向；`table()` 不按列拆分矩阵输入，用 `array2table`；横轴标签过长旋转 45°。
   - **8 项静态自检（2026-08-24 迭代新增，每个 .m 写完交付前逐项过一遍）**：
     ① 行/列向量：`1:N` 是行向量，拼接必须同列（用 `(1:N)'`）；② 约束行号统一 1 基、逐行递增无缝隙；
     ③ 锚点类右端 `1−值` 只写一次（子函数返回原始值，调用方做 1−）；④ 目标系数符号：max 转 min 取负后
     逐项核对（尤其 CVaR 的 η/v 与收益/成本项）；⑤ 隐式扩展维度（列向量×行向量产生矩阵）;
     ⑥ 链式索引 `a(b)(c)` 与脚本裸 `end`；⑦ 空 cell 提取（`find` 结果为 0×1 空，先判空再取）；
     ⑧ compose/cellstr 陷阱（compose 不接受 cellstr，用 sprintf 循环替代）。
2. 主程序存放于 `<题目名>/src/main_qX.m`（X 为问号 1~4，简单英文+字母数字标号），包含 `clear; close all; clc;`。
3. 数据读取路径：主程序顶部统一定义
   `PROJ_ROOT = fullfile(fileparts(mfilename('fullpath')), '..');  % 题目根目录（脚本位于 <题目名>/src/）`
   后续一律 `fullfile(PROJ_ROOT, 'data', '文件名')`，保证脚本从任意目录启动均可正确读取（比 fullfile(pwd,'data',...) 更健壮，且保持同风格）。
4. 所有参数在脚本顶部集中定义，代码注释标注对应数学符号（公式编号）。
5. 子函数按功能拆分，存放于 `<题目名>/src/func_<短词>_qX.m`（短词如 ols/fit/cut/pack；全局工具可不带 _qX；避免复杂英文长名）。

## 生成顺序（防止上下文溢出）
0. **小规模探针先行**（2026-08-24 迭代新增）：新模型先用微型数据（2 地块×3 作物×2 年、K=2）跑通装配与求解（秒级），验证通过后再用全量数据；探针脚本按需存 `<题目名>/scripts/probe_toy.m`（组内产物，不交付）。
1. 首先生成主程序 `main_qX.m`（含完整函数接口与公式编号注释）；
2. 随后逐个生成子函数 `func_<短词>_qX.m`（**不再单独等待接口确认**，裁决已在确认点 #1 核过）；
3. 全部生成完成后自动进入 Phase 2（/test）。
单文件超过 300 行时拆分为多个子函数文件。

## 图像生成规范（2026-08-15 初版，2026-09-05 修订，2026-09-08 重构分层）

前提：**AI 生成绘图代码、编程手人工精修细节**。故本节只写"事后难补救"与"保障可精修"两类，
其余为默认值（AI 按默认出图，编程手可随手覆盖，无需回改本规范）。

### 一、硬约束（不可覆盖，事后无法补救）
1. **300dpi + 印刷尺寸**：出图前设 `Position` 为最终尺寸（全宽 15cm / 半宽 7.5cm，同类图二选一
   不得参差），输出 PNG（入论文）+ PDF（矢量存档）；EPS 仅题目模板要求时生成。事后放大必糊。
2. **图内文字 ≥14pt**，图名与轴标签 16–18pt；"大图小字"在缩放到页宽后才暴露，出图时看不出。
3. **柱状图 y 轴必须含 0**（截断基线夸大差异是评审扣分点，非审美问题）。
4. **同一变量/类别全论文同色**，取色一律走 `func_fig_pal(idx)`，禁止散落硬编码 RGB。
   跨图一致性人工逐张调极易漏，必须由函数统一。
5. **同一指标全论文小数位一致**（如利润统一 2 位）；单位进轴标签，数据标签不带单位。
6. **图内不带图号**（图号由论文 LaTeX caption 统一编号，caption 与图内图名一致不重复）。
7. **数值/百分比标注由绘图数据现场计算**（`round(pct,1)` 等），禁止硬编码，保证与正文同源。
8. 每张图导出后立即 `close` 释放图形内存（3GB 环境）。

### 二、结构要求（保障人工精修）
1. **一图一文件夹（2026-09-11 立）**：每张图自包含于 `figures/<问题X>/<NN 图名>/`，
   内含**绘图脚本 + data.csv + PNG + PDF** 四件同目录，改图只需打开该文件夹，
   无需跨目录查找。`src/run_all_figures.m` 为汇总驱动，统一调用 `func_fig_style.m`。
2. **绘图数据先落盘再绘图**：主程序把该图所需数据写**该图文件夹内的 `data.csv`**；
   plot 脚本只读本目录 csv（`THIS_DIR = fileparts(mfilename('fullpath'))`）。
   改图无需反推数据来源、无需重跑主程序。
3. **plot 脚本内禁止数值计算**，只做取数 + 画图（标注百分比等展示性换算除外）。
4. **可调参数集中在脚本顶部 5–8 行**（尺寸、字号、色序、标注开关、小数位），改图只改这一段。
5. **图像文件名即交付中文名**（与文件夹名一致），便于人工筛选；**不再单设"交付候选"目录**。
6. 根目录定位：脚本位于 `figures/<问题X>/<图名>/`（三层深），故
   `PROJ_ROOT = fullfile(THIS_DIR, '..', '..', '..')`。

### 三、默认值（AI 按此出图，编程手可自行覆盖，不算违规）
- 调色板：主蓝 [76 114 176] / 主橙 [221 132 82] / 主绿 [85 168 104] / 主红 [196 78 82] /
  紫 [129 114 179] / 灰 [140 140 140]；单图 ≤4 色；连续量 parula 或蓝白红发散；**禁止 jet**。
- 字体：图名楷体加粗，轴标签/图例宋体，英数 Times New Roman；避免整图黑体/微软雅黑。
  Linux 出图前 `listfonts` 确认楷体/宋体可用。
- 柱状图：柱宽 0.6–0.7、无边框或白色细边；类别降序或业务序；对比图用"基准灰 + 最优强调色"。
- 标注密度：柱数少则逐柱标值，柱数多则只标关键柱、其余靠网格读数；标签偏移按轴范围比例；
  散点可隔点标注、交替错开、压点跳过、跳过 0 值。具体取舍由编程手看图决定。
- 图型：连续趋势→折线+marker（按 x 升序连线）；类别比较→柱状；类别多或名长→横向柱状/帕累托；
  占比→饼图（类别多改横向柱状）；分布→直方图/箱线图；灵敏度→龙卷风图；收敛→semilogy；
  相关矩阵→热图；量+率→双 y 轴。其余按数据性质自选。
- **禁止**（这几条不可覆盖）：装饰性 3D、jet 彩虹色、截断 y 轴柱状图、图例覆盖数据。
- 图内 LaTeX 记号优先用 Unicode（β、η、±）；必须用时显式 `'Interpreter','latex'`。

### 四、图件角色分类（**数量限制已于 2026-09-11 取消**）

> **2026-09-11 编程手裁定**：取消图件数量配额（原"总数 12–16、任一问 ≤40%、数据侧写 ≤3、
> 检验 1–2、灵敏度 ≤2"整体作废）。**出图力求完整覆盖**，最终论文选用哪些图由**人工筛选**，
> 不由配额预先裁剪。以下角色分类**保留**，仅用于图件的来源与用途标注。

| 角色 | 含义 | 论文位置 |
|---|---|---|
| 数据侧写 | 支撑建模假设的数据事实 | 数据预处理 |
| **核心结果** | 各问的主要计算结果 | 各问结果分析 |
| 检验/稳健 | 收敛、残差、误差、最优性证据 | 检验章 |
| 灵敏度 | 参数变动对结果的影响 | 灵敏度章 |

- 技术路线图/框架图**不由编程侧生成**（建模手负责，不进 figures/）。

### 五、风格离散性（与代码侧同源）
真正的机器指纹是"16 张图长得一模一样"——同边距、同标注密度、同色序轮换。
- 图件视觉手法**允许并应当在图间自然参差**；禁止全部图件由同一模板批量套出。
- 交付前抽检 3 张图：若边距、标注密度、色序完全同构，需人工分散化。
- **但第一节硬约束项（字号/dpi/同变量同色/y轴含0/小数位）不在分散化之列**——
  数据表达的严谨性必须一致，视觉呈现的手法应当参差。

## 代码风格离散性（2026-09-08 立，依据 7 篇范文横向取证）

取证结论（2026-09-08 实测复核，取证明细见 `.claude/evidence/代码风格取证_7范文.md`）：2023/2024/2025 共 7 篇范文附录代码风格**彼此不一致**——"Step N" 标记仅 2024C范文1 出现（9 处：正文 3+代码 6）；try/except 仅 2025C 两篇出现（范文1 约 6 组、范文2 2 组，提取有损为下限）；print 仅 2025C范文1 出现（6 处），2024C 三篇 0（2023C 两篇代码为图片/OCR 混合，计数待人工复核）；变量长短名混用。**竞赛代码不存在统一范式，"整齐划一"才是机器指纹。**

1. **禁止**给全项目施加统一代码风格模板；函数头注释块、分节标记、命名长度应在文件间自然参差。
2. 不得以"范文没有 X"为由禁用 X——Step 标记、try/catch、print、长变量名在范文中均有实例。
3. 已知我方痕迹（实测）：2024C+2025C 共 24 个函数**无一例外**都带 4~15 行函数头块。
   允许保留头块，但**不要求每个函数都有**；短小工具函数可只留单行或不留。
4. 交付前抽检：随机取 3 个 .m 文件，若结构高度雷同（同格式头块+同分节风格+同命名粒度）即为痕迹。

## 代码注释规范（2026-08-15 工作流迭代新增）
1. 注释只保留**思路级**内容：函数头说明块（用途/输入输出/公式编号）、`%%` 分节、
   关键行的公式编号注释；
2. 删除实现细节注释（类型转换、缓存策略、防御性处理、调试记录）；
3. 注释中不写日期、裁定过程、参考来源等过程性信息；
4. 交付前执行注释精简复查与 AI 痕迹扫描（"值得注意/不难发现/首先/其次/最后"等
   表述不得出现在注释中，技术性用语除外）。
