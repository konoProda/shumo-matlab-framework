# /prep - 题目初始化与数学建模解析

## 目标
1. 强制询问当前处理的题目名称（如"A题"，不可省略、不可猜测默认值），在 `shumo/` 下创建 `<题目名>/` 及其**强制子目录**（data/、src/、outputs/、figures/）；scripts/、tests/ 按需创建（国赛语境精简，2026-08-24）。创建完成后，在回复中回显所用的 mkdir 命令与最终目录树，供编程手核对。
2. 检查 `<题目名>/data/` 下是否存在题目所给数据文件。判定为缺失的条件：目录下无相关文件，或用户明确声明"无官方数据"。若缺失，向编程手询问模拟数据生成规则（变量维度、分布类型、参数范围、样本量）——规则必须由编程手提供，Claude 不得擅自假设分布；生成后执行预处理（标准化/正则化），并在日志与报告中标注"模拟数据"。
3. 数据格式校验：按映射表中的数据规格断言（行数/列数/类型/缺失值）。不符时给出"期望格式 vs 实际格式"对比并停止，禁止静默补零或丢弃行，由编程手澄清后再继续。
   **数值列非数值文本扫描（2025C 复盘 R7，必做）**：数值列中混存的文本数字（如截断编码 `'≥3'`）会被 readtable 静默转 NaN。须用 readcell 逐列扫描非数值文本并列出，不得只检查空值。2025C 因缺此项丢失 27.7% 记录，直到 /test 才暴露。
4. 按固定解析模板解析建模手提供的数学模型，建立"数学符号 ↔ 代码变量名 ↔ 维度"映射表。
5. 标出有歧义或缺失的信息，向编程手提问澄清。
6. **【关键确认点 #1】** 输出映射表 + 建模裁决清单（`outputs/decisions.md`）+ 求解策略后必须停止并询问确认。此时代码尚未生成，**不核对代码行号**（行号在 /report 阶段回填）。确认语义：回复含肯定词（确认/同意/OK/没问题）且不含修改意见；若回复含修改意见，先更新映射表再重新询问。进入 Phase 1 前必须在对话中复述最终版映射表。
7. **求解风险预判**（2026-08-24 迭代新增）：映射表定稿的同时，按〔连续/二值变量规模 × 约束规模 × 求解器边界（intlinprog 二值数与时限、linprog 规模与 3GB 内存、无商业求解器）〕给出定量风险评估与求解策略建议（时限+稳定性检验 / 拓扑固定法 / 降 K / 分解等）；**该策略须经编程手确认后才进入 Phase 1**。

## 解析步骤（固定模板）
1. **变量清单**：所有数学符号 → 含义 → 数据类型/维度 → 建议代码变量名。
2. **目标函数**：完整表达式 + 优化方向（min/max）。
3. **约束条件**：逐条编号（等式/不等式/上下界），标注公式编号。
4. **数据 I/O 规格**：输入文件名、格式（.xlsx/.csv/.mat）、行列含义；输出维度与含义。
5. **歧义与缺失清单**：逐条编号列出不确定处，向编程手提问。

## 输出产物
- 创建完整的题目子目录结构（回显 mkdir 命令与目录树）。
- 映射表格式（5 列：公式编号 | 数学符号 | 含义 | 数据类型/维度 | 代码变量名；每个符号标注归属：目标函数/约束 i），保存为 `<题目名>/outputs/math_to_code_mapping.md`。
- 结构化副本保存为 `<题目名>/outputs/math_to_code_mapping.json`（可选，仅当 /code 需要程序化读取时生成）。
- 预处理日志（含数据检查）保存至 `<题目名>/outputs/preprocess_log.txt`。
- **求解风险预判表**保存为 `<题目名>/outputs/solve_strategy.md`（2026-08-24 新增：规模估算/风险等级/策略建议；策略经编程手确认后随映射表一同作为 /code 输入）。
- **建模裁决清单**保存为 `<题目名>/outputs/decisions.md`（A/B/N 系列裁决 + 数据处理与平补规则；确认点 #1 的核对对象）。
- **注意**：PAPER_HANDOFF.md **不在本阶段生成**（含核心结果汇总，需代码运行后才有数据），由 /report 生成。
- 结束时将题目名写入 `shumo/.active_problem.txt`（格式：`<题目名>|Phase0`），作为后续 Phase 的操作上下文。
