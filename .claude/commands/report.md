# /report - 验证报告生成

> **逐问模式（2026-09-11）**：本次只出**当前一个问题**的结果——问题号取自 `.active_problem.txt` 第三字段，
> 或由 `/report <题目名> Qn` 显式指定。`final_results_qX.mat`、`figures/` 按问命名；
> `PAPER_HANDOFF.md` 与 `IMPLEMENTATION_REPORT.md` **保持单文件、按问追加章节**；
> 图件配额按全论文累计核算；状态文件写为 `<题目名>|Phase3|QX`。详见 CLAUDE.md §逐问求解模式。

## 触发条件
测试通过后自动触发，或用户手动输入。
- 支持显式指定题目：`/report <题目名>`（如 `/report A题`）；未指定时读取 `shumo/.active_problem.txt` 中的当前题目。
- 状态文件为空且未指定题目名时，先询问题目名，不得默认猜测。

## 图件清单前置对齐（2026-08-24 新增，2026-09-08 重构）
**（复盘固化，不可省：2024C R5、2025C 复盘再验证——重复图在清单阶段即被发现删除）**

正式出图前，先向编程手提交**图件清单表**，经确认后批量生成；禁止先出图后返工。

清单表六列：**图名 | 角色 | 代码文件 | 数据来源 | 论文位置 | 该图支撑的结论（一句话）**
（代码文件与数据来源即该图文件夹内的 `plot_qX_<图名>.m` 与 `data.csv`；图件按
`figures/<问题X>/<NN 图名>/` 一图一文件夹归档，2026-09-11 立）

- **角色**取值：数据侧写 / 核心结果 / 检验稳健 / 灵敏度（定义与配额见 code.md §四）。
- **"支撑的结论"写不出来的图，即判定为不该存在**——这是最有效的图件裁剪器。
- 配额校验（不满足则打回重排）：总数 12–16 张；任一问 ≤ 总数 40%；
  数据侧写 ≤3 且不得 ≥ 核心结果张数；灵敏度 ≤2。
- 技术路线图/框架图由建模手负责，不进本清单、不占配额。

出图后核对（六项，其余硬约束已在 code.md §一 固定，此处不重复）：
① 图型与数据性质相符；② 图名位于图下方且无图号前缀；③ LaTeX 已渲染无 `$` 残留；
④ 标注不重叠、不被轴裁切；⑤ 灰度化后仍可区分；⑥ 图像文件名与同目录 `plot_qX_*.m` 一一对应。

图件与结果表清单（含角色列与代码文件列）最终写入 PAPER_HANDOFF.md。

## 正式运行
1. 清空内存，读取 `<题目名>/data/` 下的完整原始数据。
2. 运行 `<题目名>/src/main_*.m`，记录总耗时。
3. 结果存至 `<题目名>/outputs/final_results.mat`（save 使用 fullfile 绝对路径，避免默认路径依赖），图表存至 `<题目名>/figures/`。

## 交付打包（2026-08-24 新增，国赛语境）
收尾时生成 `<题目名>/deliver/` 作为**唯一交付面**：
- **必含**：result1_1/result1_2/result2.xlsx（题目要求结果，官方模板）、`code/`（main_*.m + 全部 func_*.m + 核心可复现脚本）、论文.pdf（如有）；
- **可选**：data/（附件）、figures/（图件）、README_运行说明.md；
- **不交付**：tests/、outputs/ 日志与中间记录、映射表/风险预判、IMPLEMENTATION_REPORT、PAPER_HANDOFF、RETROSPECTIVE（组内文档）。

## 实现验证报告 (`<题目名>/IMPLEMENTATION_REPORT.md`)
结构如下：
- 〇、执行摘要：一句话结论（全部测试通过/存在失败项）+ 关键指标（总耗时、稳定性、最大误差）。
- 一、数学→代码映射表
- 二、运行记录（数据规模、耗时、内存）
- 三、测试验证结论（各测试项结果）
- 四、代码质量与风险提示：
  - 代码结构：主程序+子函数分离，参数集中管理；
  - 向量化程度：按"src/ 计算主体中显式 for/while 循环体数量"分级：≤2 → 高；3–5 → 中；>5 → 低（须列出最耗时循环的文件与行号）；
  - 已知警告/边界风险：列出。

## 论文交接文档（本阶段生成）
- `<题目名>/PAPER_HANDOFF.md`：建模概述 / 代码与求解概述 / **核心结果汇总（每个数字标注出处文件）** /
  检验与稳健性 / 图件与结果表清单。**因含运行结果，只能在正式运行后生成，不得前移至 /prep。**
- 映射表回填各建模裁决对应的代码位置（文件:行号）。

## 【关键确认点 #2】
IMPLEMENTATION_REPORT.md 生成后**停止**，等待编程手确认风险清单（10-15 分钟）：
风险是否完整、每条是否标注论文对应位置、口径是否诚实。模板见 `_CHECK_TEMPLATES.md` 模板2。

同时生成 `<题目名>/建模手交接/交付建模手/致建模手_确认点2_qX.md`（2026-09-11 新增，见 CLAUDE.md §确认点交付单）：
列出需建模手回复的少数项（如口径确认、结果是否与建模预期相符）+ 仅告知项 + 填写式回复区，
**不出现代码与求解器细节**；编号须与 `IMPLEMENTATION_REPORT.md` 的风险清单一一对应。

## 收尾
交付后核对六件套：状态置 Done、PAPER_HANDOFF、IMPLEMENTATION_REPORT、**RETROSPECTIVE.md**、
deliver/ 已打包、三确认点记录留档。RETROSPECTIVE 不可省——它是下次工作流优化的唯一流程依据。

## 交付确认
报告生成后回复："✅ 题目 [题目名] 代码实现验证完成，报告已生成于 `<题目名>/IMPLEMENTATION_REPORT.md`。"
