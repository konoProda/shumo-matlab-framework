# 论文写作项目规范（paper-spec）

> 本规范适用于 shumo/ 下**所有题目**的论文写作任务，由编程手于 2026-08-15 制定。
> 与 paper-writer（写作与排版规范）、humanizer（去 AI 腔）两个 skill 配套使用。

## 一、输出格式与文件组织

1. **一律使用 LaTeX 生成**，输出目录固定为 `<题目名>/paper/`，自包含、可直接打包提交：
   ```
   <题目名>/paper/
   ├── main.tex                 # 主文件（\input 各章节）
   ├── sections/                # 章节拆分: abstract/restatement/assumption/symbol/
   │                            #           q1/q2/q3/q4/verification/evaluation/appendix
   ├── figures/                 # 论文用图（从 ../figures/ 复制所需 PNG/EPS）
   ├── tables/                  # 论文用表格（.tex 片段）
   └── README.md                # 编译说明（xelatex 流程）与打包说明
   ```
2. 中文论文 → 使用 ctex 文档类，`\documentclass[12pt,a4paper]{ctexart}`；数学环境用 amsmath。
3. 图表引用：`\includegraphics{figures/xxx.png}`（相对 main.tex 的路径），保证打包后可直接编译。
4. 生成后提供编译检查建议（xelatex 编译命令），编译排错由我协助。

## 二、篇幅要求

- **全文 25~30 页**（正文 + 图表 + 公式，不含附录；附录可另计页数）。
- 控制手段：章节字数预算制——摘要 1 页内；问题重述+分析 ≤2 页；每问模型建立与求解 4~6 页；检验 1.5~2 页；评价 1 页。
- 宁缺毋滥：不灌水、不堆公式、不贴无用图。

## 三、写作素材与真实性底线

1. 素材唯一来源：`<题目名>/PAPER_HANDOFF.md` + `outputs/` 结果表 + `figures/` 图表。
2. **禁止虚构**：数据、参数、结果数字、图表结论、参考文献必须与实际运行一致。
3. 论文正文数字与代码输出不一致时，以代码输出为准并修正论文。

## 四、逐章确认机制

1. 按章节顺序推进：摘要 → 问题重述与分析 → 假设与符号 → 问题一 → 问题二 → 问题三 → 问题四 → 检验与敏感性 → 模型评价 → 参考文献与附录。
2. **每完成一章，向编程手展示并请其确认**；确认后才进入下一章。
3. 写作中出现任何疑问（口径、表述、取舍），**先向编程手提问并附建议**，不得自行决定。

## 五、两个 skill 的用法

- **paper-writer**：结构与表达的规范来源（摘要五问、问题分析转化、模型闭环、结果分析顺序、检验匹配、评价三要素、图表公式排版、硬性禁止）。
- **humanizer**：每章初稿完成后执行去 AI 腔修订。**学术适配**：保留加粗表头/编号列表/公式编号；不套用"加幽默/第一人称"规则；重点清除 AI 高频词、破折号滥用、三连排比、空洞升华句、整齐对称句式。

## 六、参考同题论文的边界（反抄袭红线）

1. 可参考：**结构组织方式、图表类型选择、排版风格**。
2. 不可照搬：章节标题句式、过渡语句、解释措辞、公式排版细节的组合方式；叙述角度与顺序必须不同。
3. 论文必须**展现本队建模独特性**（如本队的创新点、处理细节、敏感性设计），避免与任何同题论文产生可察觉的相似。
4. 如需引用参考论文，仅在参考文献列表中出现，正文不提及"某范文"字样。

## 七、代码展示原则（v2, 2026-08-15 修订）

1. 正文不贴代码，用文字描述算法流程。
2. **附录A**：支撑材料目录（按问题列出代码文件/数据文件/图表清单，同题范文惯例）。
3. **附录B：核心代码**，展示完整算法块而非短片段：主程序全文（流水线总览）+
   核心算法函数全文（如评价方法函数）+ 各问的关键求解段（目标函数构建与求解循环），
   数据处理与绘图代码不进附录。附录B 总量 ≤6 页（附录合计 ≤8 页，不计入正文页数预算）。
4. **注释规范**：块首一行说明算法步骤与对应公式编号；关键行保留公式编号注释；
   **删除实现细节注释**（类型转换/缓存/防御处理）；注释只表"做什么、对应哪个公式"，
   不解释"为什么这么写"。
5. 代码排版用 verbatim 环境 + \footnotesize，保持朴素无语法高亮；代码逻辑必须与
   支撑材料中的实际代码一致（仅删注释，不改逻辑）。
6. 完整代码随支撑材料提交，README 说明清单。

## 八、个人信息留空

- 作者姓名、学校、队号等一律用占位符（如【学校名称】【队员1姓名】）留空，由编程手提交前填充。

## 九、交付前自检清单

- [ ] 30 页以内；摘要一页内可读完
- [ ] 每张图表在正文中被引用且有前后解释句
- [ ] 所有数字与 outputs/ 一致
- [ ] 无 AI 腔残留（humanizer 复查通过）
- [ ] 无可察觉抄袭痕迹（参考论文仅出现于参考文献）
- [ ] 个人信息占位符就位
- [ ] paper/ 目录自包含，可独立编译打包
